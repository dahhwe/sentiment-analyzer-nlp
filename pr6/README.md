# Практическая работа №6: Диалоговая подсистема генератора синтетических данных (поиск, seq2seq, гибридный чат-бот)

Тема магистерской диссертации – «Система генерации синтетических данных для обучения ML алгоритмов детекции объектов».
Программный продукт – генератор synthfire: набор скриптов для Blender, которые строят случайную лесную сцену с дымом
и пламенем, рендерят ее как с камеры БПЛА и сами размечают кадры для детекторов (YOLO, COCO). В этой работе для него
сделана диалоговая подсистема: чат-бот, который отвечает пользователю генератора на вопросы о запуске, параметрах
сцены, разметке и структуре датасета, а также принимает отзывы о кадрах.

По заданию нельзя использовать шаблонный генератор, поэтому ответ выбирается гибридом подходов из лекции 12:
информационный поиск по корпусу пар «высказывание – ответ», порождающая модель sequence-to-sequence, поиск по README
генератора (роль поисковой системы) и уточняющий вопрос, если ответа нет. Для поиска по плотным векторам используется
индекс приближенного поиска ближайших соседей из лекции 13. Ответы бота сравниваются с генератором на шаблонах из
[Практической работы №5](../pr5).

## 1. Соответствие требованиям ТЗ и устройство системы

### 1.1 Использование результатов ПР1–ПР5

- **ПР1** – `RegexTokenizer` и `TextNormalizer`: лемматизация pymorphy3, привязка отрицаний («не_разметить»), замена
  синонимов. Для диалога сделаны два изменения (класс `DialogNormalizer`): стоп-слова не удаляются, потому что в
  репликах «Кто ты?» или «Как дела?» кроме них ничего нет, и убрана замена сленгового «огонь» на «хороший», которая
  была нужна для отзывов, а в разговоре о пожарах ломает смысл. Для поиска по README используется полный конвейер ПР1.
- **ПР2** – настройки векторизатора TF-IDF (леммы как токены, `sublinear_tf`), но без `min_df=2`: этот порог
  выбрасывает слова, которые есть только в одном высказывании, а это часто самые характерные слова вопроса.
  `LSAModel` участвует в сравнении подходов.
- **ПР3** – модель Word2Vec. Около 39 % лемм диалогов и README в ней нет («blender», «yolo», «датасет», «видеокарта»),
  поэтому ее копия дообучается на текстах предметной области. Дообученные векторы дают плотные представления реплик
  и начальные веса слоя `Embedding` кодировщика seq2seq. Исходная модель ПР3 остается для сетей тональности.
- **ПР4** – обученная CNN и функции `tokenize_and_vectorize`, `pad_trunc`: тональность реплик пользователя.
- **ПР5** – сеть LSTM (тональность вместе с CNN), архитектура seq2seq (кодировщик и декодировщик на LSTM, обратный
  порядок слов на входе, `return_state`, жадное декодирование), которая из автокодировщика превращена в модель
  «реплика → ответ». Генератор на шаблонах `TemplateGenerator` и выделение фактов `extract_facts` – база для сравнения.

### 1.2 Данные (`data/`)

| Файл                  | Содержимое                                                                                      |
|-----------------------|-------------------------------------------------------------------------------------------------|
| `dialogs.csv`         | 56 тем, в каждой 5–6 высказываний пользователя и один ответ, всего 289 высказываний             |
| `synthfire_readme.md` | копия README генератора, из нее получается 73 фрагмента (абзацы, пункты списков, строки таблиц) |
| `test_questions.csv`  | 71 отложенная реплика: 67 перефразировок по темам корпуса и 4 вопроса не по теме                |
| `my_messages.txt`     | пользовательские данные: 14 реплик одного разговора с ботом                                     |

Ответы в `dialogs.csv` написаны только по фактам из README генератора. Как советует лекция, требования к боту
составлены в виде таблицы «высказывание → ответ», причем одному ответу соответствует несколько вариантов вопроса.
Отложенные реплики в корпус не входят, по ним сравниваются подходы.

### 1.3 Как выбирается ответ (`chatbot/dialog.py`)

1. Реплика нормализуется. Реплика, начинающаяся с «а» или «и» («А в высоком качестве?»), дополняется леммами
   предыдущей: так бот помнит контекст разговора.
2. Если после нормализации реплика дословно совпадает с высказыванием корпуса («Привет!»), отвечает его тема.
3. **Информационный поиск.** Документ корпуса – леммы высказывания вместе с леммами ответа темы. Оценка документа
   равна 0.7 · сходство TF-IDF + 0.3 · сходство средних векторов Word2Vec, оценка темы – лучшая оценка ее высказываний.
4. **Порождающая модель.** Seq2seq пишет ответ на реплику. Если он совпадает с ответом темы, которая отстает от лучшей
   темы поиска не больше чем на 0.1, выбирается эта тема: когда поиск не уверен, решает второй подход.
5. **Фильтр тональности.** Темы, высказывания которых уверенно противоположны реплике по тональности (CNN + LSTM,
   вероятность класса не меньше 0.6), получают штраф 0.1.
6. Если оценка темы не меньше 0.4, бот отвечает ответом темы. Иначе он ищет фрагмент README (порог тоже 0.4), а если
   не находит и его, честно говорит, что не понял, и задает уточняющий вопрос. Варианты вопроса чередуются, чтобы бот
   не повторялся, а на уверенно негативную реплику бот просит описать проблему.

Шестой пункт – советы из раздела «Полезности» лекции 12: уточняющий вопрос вместо ответа невпопад, честность,
не повторяться слишком часто и сыграть роль поисковой системы по базе знаний.

### 1.4 Порождающая модель seq2seq (`chatbot/generator.py`)

Кодировщик: `Embedding` (100, веса из дообученного Word2Vec, обучаемый, `mask_zero`) → `LSTM(128, return_state=True)`.
Декодировщик: `Embedding(64)` → `LSTM(128)` с начальным состоянием от кодировщика → `Dense` с softmax по 916 токенам.
Токены ответа – слова вместе со знаками препинания («кадров,»), поэтому ответ собирается простым соединением через
пробел, а векторы декодировщика обучаются с нуля. Обучение «с усилением учителем», `adam`, до 300 эпох, пакет 16.
Параметров 436 352: 4 · (100 + 128 + 1) · 128 = 117 248 в LSTM кодировщика, 4 · (64 + 128 + 1) · 128 = 98 816
в LSTM декодировщика, 128 · 916 + 916 = 118 164 в выходном слое и 435 · 100 + 916 · 64 = 102 124 в слоях `Embedding`.
Для генерации, как в ПР5, отдельно собираются `encoder_model` и `decoder_model`, слова выбираются по одному, пока
декодировщик не выдаст `<конец>`.

### 1.5 Поиск и индекс (`chatbot/search.py`)

Векторы TF-IDF разреженные, и сходство со всеми документами считается точно и быстро. Средние векторы Word2Vec
плотные, а в лекции 13 показано, что для плотных векторов обычные индексы баз данных не работают, а выбор ответа
чат-ботом перебором имеет сложность O(N). Поэтому плотные векторы хранятся в индексе приближенного поиска Voyager
(граф HNSW, как в nmslib из лекции). Кандидаты из индекса и из TF-IDF объединяются и оцениваются итоговой формулой.
На 289 документах индекс скорость не меняет, поэтому, как в лекции с Annoy и `most_similar`, он проверен на всем
словаре Word2Vec (пример А).

### 1.6 Обучение и сохранение

Word2Vec дообучается 20 эпох на 289 высказываниях, 56 ответах и 73 фрагментах README: словарь растет с 14 660 до
14 986 слов, это занимает доли секунды. Модель сохраняется в `models/word2vec_domain.model`. Seq2seq обучается около
3 минут на двухъядерном процессоре (300 эпох, ошибка падает до конца, поэтому `EarlyStopping` по ошибке не
срабатывает), веса сохраняются в `models/generator.weights.h5`, словари в `models/generator.json`.

## 2. Обоснование используемых библиотек

- **TensorFlow / Keras** – модель seq2seq на функциональном API, слои `LSTM` и `Embedding`.
- **voyager** – индекс приближенного поиска ближайших соседей (HNSW) от Spotify, преемник Annoy из лекции. У Annoy
  на PyPI нет готовых пакетов, и на Windows его не установить без компилятора C++, а у Voyager есть готовые пакеты
  для Python 3.9–3.12.
- **gensim** – дообучение модели Word2Vec из ПР3.
- **scikit-learn** – `TfidfVectorizer`, LSA из ПР2.
- **pymorphy3, nltk** – нормализация из ПР1, согласование слов в генераторе на шаблонах ПР5.
- **numpy, pandas** – работа с массивами и CSV.

### Шаг 5. Развертывание в проекте генератора

Бот можно запускать отдельно (`python main.py --chat`) или подключить из кода генератора:

```python
import sys

sys.path.append("путь/к/sentiment-analyzer-nlp/pr6")
from main import Assistant

assistant = Assistant()
print(assistant.engine.respond("Как запустить генерацию?")["reply"])
```

Когда README генератора меняется, достаточно заменить `data/synthfire_readme.md` или указать путь к новому файлу
параметром `--readme`. Новые пары «вопрос – ответ» добавляются в `data/dialogs.csv`, после чего модели обучаются
заново командой `python main.py --train`.

## 4. Подбор параметров

Вес TF-IDF в оценке документа (accuracy выбора темы на 67 отложенных репликах / при скользящем контроле на
289 высказываниях корпуса, когда каждое высказывание ищется среди остальных):

| Вариант                       | Word2Vec ПР3 | Дообученный Word2Vec |
|-------------------------------|--------------|----------------------|
| Только Word2Vec               | 0.22 / 0.21  | 0.30 / 0.26          |
| 0.5 · TF-IDF + 0.5 · Word2Vec | 0.51 / 0.40  | 0.58 / 0.49          |
| 0.7 · TF-IDF + 0.3 · Word2Vec | 0.51 / 0.46  | **0.60 / 0.50**      |
| 0.9 · TF-IDF + 0.1 · Word2Vec | 0.60 / 0.51  | 0.58 / 0.50          |
| Только TF-IDF                 | 0.58 / 0.49  | 0.58 / 0.49          |

- Одни векторы Word2Vec ищут плохо даже после дообучения. Модель ПР3 обучена на отзывах, и несколько сотен реплик
  этого не перебивают: у слова «кадр» ближайшие соседи «этический» и «обычай» (кадры как персонал). Новые слова
  выучиваются лучше: у «видеокарта» соседи «blender», «nvidia», «драйвер».
- В смеси с TF-IDF дообученные векторы дают небольшой прирост (+0.015 на тесте, то есть одна реплика) и делают
  результат менее чувствительным к весу. Итоговый вес 0.7 выбран по скользящему контролю.
- Документ «высказывание + ответ» лучше, чем одно высказывание: при скользящем контроле 0.50 против 0.37. В ответе
  есть термины, которыми пользователь задает вопрос, а в коротком высказывании их часто нет.
- Пробовал добавить символьные триграммы (в лекции 13 упоминаются триграммные индексы): на тесте 0.63–0.64, при
  скользящем контроле 0.51–0.53, то есть прирост в пределах двух-трех реплик. Усложнять поиск ради этого не стал.

Правило выбора между поиском и seq2seq (accuracy на 67 отложенных репликах):

| Правило                                                    | Accuracy  |
|------------------------------------------------------------|-----------|
| Только поиск                                               | 0.597     |
| Только seq2seq                                             | 0.463     |
| Тема seq2seq, если она среди трех лучших тем поиска        | 0.657     |
| Тема seq2seq, если отстает от лучшей не больше чем на 0.2  | 0.612     |
| Тема seq2seq, если отстает от лучшей не больше чем на 0.1  | **0.731** |
| Тема seq2seq, если отстает от лучшей не больше чем на 0.05 | 0.716     |

Seq2seq обучен на всех высказываниях корпуса, поэтому скользящим контролем его не проверить, и правило подбиралось на
тех же отложенных репликах. Значит, оценка 0.731 немного завышена, но то, что два подхода вместе лучше каждого
по отдельности, видно при любом правиле.

Порог ответа выбран по скользящему контролю (пример А): при пороге 0.35 бот отвечает на 83 % реплик, но правильно
лишь в 54 % случаев, при 0.5 отвечает только на 18 %. Порог 0.4 – компромисс. Для поиска по README сначала
использовались те же леммы со стоп-словами, и вопросы не по теме набирали 0.35–0.42 («Как приготовить борщ?» находил
фрагмент «Основной рендер даёт фотографию»). После удаления стоп-слов такие вопросы набирают 0.13–0.20, а подходящие
фрагменты около 0.4–0.6.

Фильтр тональности на отложенных репликах и на 12 эмоциональных фразах («Разметка отличная, спасибо!», «Ночные кадры
ужасные» и т. п.) не изменил ни одного выбора. Сети уверены только в явных оценках, а слова «ужасный» или «отличный»
и так приводят к темам жалобы и похвалы. Фильтр оставлен по совету лекции, а тональность еще используется для выбора
уточняющего вопроса.

| Реплика не по теме            | ответ по тональности, как на отзыв             | уточняющий вопрос (3 из 4) или ответ невпопад (1 из 4)        |

Выводы:

- Генератор на шаблонах отвечает только на тональность. На 14 реплик он выдал 12 разных текстов, но ни один не
  отвечает на вопрос: на «Привет!» он благодарит за отзыв, полезный «другим читателям». К тому же LSTM, обученная
  на отзывах длиной в десятки слов, назвала негативными 8 реплик из 14, хотя жалоб во всем разговоре три, и одну из
  них («Кадры ночью получаются очень темные») как раз сочла нейтральной. Поэтому на «Как запустить генерацию на
  100 кадров?» и даже на «Пока!» шаблоны приносят извинения. После обучения цепочки с нуля та же LSTM сочла
  негативными уже 2 реплики из 14: на коротких репликах ее оценка почти случайна. Поэтому в ПР6 тональность влияет
  на ответ, только когда сети уверены (порог 0.6).
- Бот отвечает по существу, но обратная сторона в том, что ответ берется из корпуса целиком: на вопрос про 100 кадров
  он дает общую команду с `--count 5` и `--count 1000`, а не подставляет число 100. Шаблоны умеют подставлять
  факты из текста, но не знают, что ответить.
- Ошибки бота на пользовательских данных типичны для информационного поиска. Слово «сегодня» в корпусе встречается
  только в прощании «На сегодня все», поэтому «Какой сегодня курс доллара?» набрал 0.47 и получил прощание, а seq2seq
  с этим согласился. Про видеопамять в README ничего нет, и бот ответил ближайшей темой о скорости рендера. Порог
  0.4 отсекает большинство вопросов не по теме (3 из 4 на тесте), но не все.
- Seq2seq ни разу не написал нового текста: на 289 обучающих репликах он дословно воспроизводит ответ, а на любой
  другой реплике выдает один из ответов корпуса, на «Как приготовить борщ?» ответ на «Как дела?». После обучения
  с нуля модель один раз все же написала новый текст: на «Хочу кадры в Full HD» – «До свидания! Удачной это
  процедурная модель шлейфа, а не расчет гидродинамики. Формы правдоподобны,». Это склейка начала одного ответа
  и середины другого. Все это совпадает с лекцией 12: порождающей модели нужны большие корпуса диалогов, а на
  289 парах она по сути превратилась в классификатор тем, и писать ответы самостоятельно ей доверять нельзя.
  Одна она точнее только Word2Vec (0.463), но как второй голос поднимает поиск с 0.597 до 0.731.
- Итог: шаблоны дают предсказуемый и всегда грамматичный текст, но для диалога с пользователем генератора не подходят,
  потому что не знают ответов. Гибрид поиска и seq2seq отвечает правильно на 40 из 67 отложенных реплик
  (точность ответов 0.82), а когда не уверен, задает уточняющий вопрос. Слабые места – вопросы, которых нет в корпусе,
  и случайные совпадения редких слов. Их можно уменьшить, пополняя `dialogs.csv` реальными вопросами пользователей.

# synthfire – генератор синтетического датасета лесных пожаров

Скрипты для Blender, которые строят случайную лесную сцену с дымом и пламенем,
рендерят её «как с камеры БПЛА» и сами пишут разметку для детекции объектов.
Ручной работы в редакторе нет: всё задаётся конфигурацией и зерном генератора.

Классы: `0 – smoke` (дым), `1 – fire` (пламя). Нумерация как в D-Fire.

## Что нужно

- Blender **5.2 LTS** или новее (проверено на 5.2.3 и 5.3.0). В более старых версиях API отличается.
- Видеокарта NVIDIA с актуальным драйвером (рендер через OptiX или CUDA). Без неё работает на процессоре, но медленно.
- Python отдельно ставить не нужно: у Blender свой. Для скриптов из `tools/` подойдёт любой Python 3.9+ с numpy.

## Запуск

Windows, двойной щелчок или из консоли:

```
run_windows.bat --count 5
```

Или напрямую:

```
"C:\Program Files\Blender Foundation\Blender 5.2\blender.exe" -b -P generate.py -- --out D:\datasets\synthfire --count 1000
```

Основные параметры (после `--`):

| Параметр | Что делает |
|---|---|
| `--out ПАПКА` | куда писать датасет |
| `--count N` | сколько кадров сделать |
| `--start K` | с какого номера начать (для продолжения или запуска частями) |
| `--config ФАЙЛ` | конфигурация, по умолчанию `configs/default.toml` |
| `--width`, `--height`, `--samples` | разрешение и число лучей на пиксель |
| `--device AUTO\|OPTIX\|CUDA\|CPU` | устройство рендера |
| `--seed S` | зерно датасета |
| `--overwrite` | перерисовать уже готовые кадры |
| `--scenario meta/000123.json` | перерисовать один кадр точно по сохранённому сценарию |

Готовые кадры пропускаются, поэтому прерванный запуск можно просто повторить той же командой.
Первый запуск на видеокарте дольше остальных: Blender один раз компилирует ядра рендера.

Начните с `--count 5`, откройте папку `preview` и убедитесь, что рамки стоят на дыме.

### Качество и скорость

- `configs/default.toml` – 1280×720, 128 лучей на пиксель. Основной режим.
- `configs/hq.toml` – 1920×1080, 192 луча. Примерно в 3 раза медленнее:
  `run_windows.bat --config configs\hq.toml --count 5`.

Размытие объектива по умолчанию выключено (`sensor.blur = [0, 0]`), JPEG сохраняется с качеством 92–97.
Размытие, шум и сжатие проще добавлять аугментациями при обучении, чем убирать из готового датасета.
В консоли для каждого кадра печатается, сколько секунд ушло на рендер, на разметку и на остальное.

## Что получается

```
dataset/
  images/000000.jpg          кадр
  labels/000000.txt          разметка YOLO: класс cx cy w h (в долях кадра)
  masks/000000.png           маска классов: 0 фон, 1 дым, 2 огонь
  opacity/000000_smoke.png   карта видимой непрозрачности дыма (канал = номер очага)
  opacity/000000_fire.png    то же для пламени
  meta/000000.json           полный сценарий кадра и список объектов
  preview/000000.jpg         кадр с нарисованными рамками, для просмотра
  annotations/instances_{train,val,test,all}.json   разметка COCO (рамки и маски RLE)
  splits/{train,val,test}.txt
  dataset.yaml               описание датасета для Ultralytics YOLO
  stats/frames.csv, objects.csv, summary.json       статистика
  config_used.json           конфигурация, с которой шла генерация
```

Разбиение на train/val/test делается по сценам, а не по кадрам: ракурсы одной сцены
не попадают в разные части.

## Как устроена разметка

Дым полупрозрачен, поэтому готовых «масок объектов» рендер для него не даёт.
Здесь рамка получается так:

1. Основной рендер даёт фотографию.
2. Вспомогательный рендер той же сцены: света нет, все поверхности чёрные,
   а дым каждого очага и поглощает, и излучает с одинаковой плотностью.
   По модели эмиссии–поглощения яркость пикселя тогда равна видимой непрозрачности
   дыма `1 − T`, уже с учётом деревьев, рельефа, тумана и других шлейфов перед ним.
   Каждый очаг пишется в свой цветовой канал, поэтому объекты не сливаются.
3. Такой же проход для пламени; дым в нём только поглощает, так что пламя, скрытое
   плотным дымом или кронами, в разметку не попадает.
4. Карта сглаживается и сравнивается с порогом; рамка – границы полученной маски.
   Порог равен большему из двух значений: абсолютного `tau` и доли `tau_rel` от пиковой
   непрозрачности объекта. Первое сохраняет слабый дым, второе не даёт тонкой вуали вокруг
   плотного шлейфа раздувать рамку.
5. Проверка заметности дыма. Та же сцена рендерится ещё раз без дыма, в половинном
   разрешении. Если удаление шлейфа меняет картинку меньше, чем на `min_contrast`,
   шлейф не размечается. Отброшенные объекты записаны в `meta/*.json` в поле `rejected`.
   Слишком мелкие объекты тоже отбрасываются (`min_area`, `min_side`).

Дымка и туман в проходах разметки работают как поглотители. По закону Кошмидера
контраст объекта падает с расстоянием так же, как пропускание, поэтому далёкий дым
в плотной дымке перестаёт размечаться примерно там же, где перестаёт быть виден.

Карты непрозрачности сохраняются, поэтому порог можно поменять без повторного рендера:

```
python tools/relabel.py --out D:\datasets\synthfire --tau-smoke 0.2 --labels-dir labels_tau020
```

## Что меняется от кадра к кадру

- **Местность:** рельеф, водоёмы, поляны, болота, вырубки, лесная дорога.
- **Лес:** густота, доля хвойных, сезон (лето, конец лета, осень, весна), сухостой.
- **Время суток:** день, низкое солнце (рассвет и закат), сумерки, ночь со слабым свечением
  неба и иногда с луной. Доли задаются в `[weather.daytime]`.
- **Погода:** ясно, дымка, переменная облачность (облака на небе и их тени на земле),
  пасмурно, задымление от других пожаров, туман в низинах.
- **Пожар:** от 0 до 3 очагов, четыре стадии от возгорания 1,5–5 м до верхового 45–110 м,
  тление без пламени, выгоревшая площадь, опалённые деревья, цвет и плотность дыма.
- **Ветер:** наклон и вытянутость шлейфа, наклон пламени, форма гари.
- **Камера:** высота 60–400 м, дальность 150–1200 м, наклон от горизонта до отвесного,
  три диапазона угла обзора, небольшой крен.
- **Сенсор:** автоэкспозиция с пределом усиления, баланс белого, шум (растёт в сумерках
  и ночью), виньетирование, ореол вокруг пламени, сжатие JPEG.

Отрицательные примеры: сцены без пожара (15 %), туман в низинах, дымка,
блики на воде, осенняя листва.

Все диапазоны и вероятности лежат в `configs/default.toml` с комментариями.

## Воспроизводимость

Кадр с номером `N` полностью определяется зерном датасета и `N`. Сценарий каждого
кадра сохранён в `meta/N.json`; по нему кадр можно перерисовать:

```
blender -b -P generate.py -- --out D:\tmp\rerender --scenario D:\datasets\synthfire\meta\000123.json
```

Геометрия и разметка при этом совпадают. Шум рендера на видеокарте и на процессоре
немного различается, поэтому пиксели совпадают не бит в бит.

## Ограничения

- Деревья процедурные и упрощённые. С высоты от 60–80 м лес выглядит правдоподобно,
  на близких низких ракурсах видна условность крон.
- Дым – процедурная модель шлейфа, а не расчёт гидродинамики. Формы правдоподобны,
  но нет временной динамики: соседние кадры не образуют видео.
- Ночью размечается только то, что видно на кадре: пламя и дым, подсвеченный огнём.
  Неосвещённый дым проверку заметности не проходит и остаётся в `rejected`.
- Облака – плоский слой на небе и тени на земле. Объёмных облаков, дождя и снега нет.
- За пределами круга радиусом 1,2 км деревья заменены текстурой полога, поэтому камера
  держится не дальше 800 м от центра сцены. Для более дальних планов увеличьте `forest.radius`.
- Пламя – светящийся объём вдоль кромки пожара; вблизи оно выглядит упрощённо.
- Реалистичность не измерена на реальных данных. Проверить её можно только сравнением
  с реальными снимками или обучением модели.

## Что проверено

- Генерация и разметка: Blender 5.2.3 (модуль `bpy`), Linux, рендер на процессоре, 640×360.
  Все типы погоды и стадии пожара прошли без ошибок.
- Проход разметки сверен с эталоном высокой точности: совпадение масок (IoU) 0,98–0,99,
  границы рамки отличаются не больше чем на 1–2 пикселя.
- Повторный рендер по сохранённому сценарию на той же машине даёт тот же кадр и ту же разметку.
- Запуск на Windows 11 с RTX 3050 Ti (OptiX), Blender 5.3.0, 1280×720: версия 0.1 отработала
  без ошибок, 46–66 секунд на кадр.
- **Не проверено на видеокарте:** изменения версии 0.2 (ночь, сумерки, облака, новые настройки
  качества) и режим `hq.toml`. Они проверены только на процессоре в 640×360.
  Папка `examples/` содержит черновые кадры с процессора, по ним видно структуру датасета.

## Что изменилось в версии 0.2

- Исправлено размытие: при `sensor.blur` больше 0,3 кадр размывался в 2–4 раза
  сильнее заданного. Теперь размытие точное и по умолчанию выключено.
- Больше лучей на пиксель, шумоподавление с опорой на альбедо и нормали, выше качество JPEG.
- Время суток: добавлены сумерки и ночь, луна, предел усиления камеры.
- Видимые облака на небе при переменной облачности, лёгкие облака в ясную погоду,
  неоднородное пасмурное небо.
- Рамки: относительный порог `tau_rel`; мелкое пламя размечается начиная с 2 пикселей,
  рамка при этом не меньше `min_side`. Проверка заметности дыма учитывает шум матрицы ночью.
- В журнале и в `meta/*.json` время кадра разбито на этапы; в статистике есть время суток.
- Режим `configs/hq.toml`.

## Структура кода

| Файл | Назначение |
|---|---|
| `generate.py` | точка входа, цикл по кадрам |
| `synthfire/scenario.py` | случайный сценарий: сцена, погода, пожары, камера, сенсор |
| `synthfire/terrain.py` | рельеф и карты покрытия (numpy) |
| `synthfire/vegetation.py` | модели деревьев, материал, расстановка |
| `synthfire/atmosphere.py` | небо, дымка, туман, тени облаков |
| `synthfire/fire.py` | шлейф дыма, пламя, свет от огня, режимы материалов |
| `synthfire/scene.py` | сборка сцены Blender из сценария |
| `synthfire/render.py` | проходы рендера, модель камеры и сенсора |
| `synthfire/annotate.py` | маски, рамки, YOLO, RLE, PNG |
| `synthfire/index.py` | разбиение, COCO, статистика |
| `synthfire/nodes.py` | запись графов узлов Blender формулами Python |
| `tools/build_index.py` | пересобрать разбиение, COCO и статистику |
| `tools/relabel.py` | пересчитать разметку с другим порогом |
